## Docker run和Docker Compose
| 对比项 | `docker run` | Docker Compose |
|---|---|---|
| 配置形式 | 一条命令 | YAML 配置文件 |
| 适合场景 | 临时测试、单个简单容器 | 正式部署、多容器系统 |
| 参数保存 | 依赖脚本、命令历史 | 保存在 `compose.yml` |
| 多服务管理 | 每个容器单独操作 | API、MySQL、Qdrant 可统一管理 |
| 修改配置 | 通常重新写一遍长命令 | 修改 YAML 后重新部署 |
| 网络 | 手工创建和指定 | 自动创建项目网络 |
| 启停 | `docker start/stop` | `docker compose up/down` |
| 可维护性 | 容易遗漏参数 | 更容易审查、备份和迁移 |

### Docker run
配置全部写在命令里：
```shell
docker run -d \
  --name demo-ai \
  --restart always \
  -p 8100:8100 \
  -e TZ=Asia/Shanghai \
  -v /data/demo:/app/data \
  demo:latest
```
**缺点**是几个月后可能没人知道当初用了哪些端口、目录、环境变量和网络参数。

### Docker Compose
相同配置保存为文件：
```shell
services:
  contract-api:
    image: demo:latest
    container_name: demo-ai
    restart: always

    ports:
      - "8100:8100"

    environment:
      TZ: Asia/Shanghai

    volumes:
      - /data/demo:/app/data
```

部署：
```shell
docker compose up -d
```
修改配置后强制部署：
```shell
docker compose up -d --force-recreate xxx
```

## 完整命令
1. 本地构建镜像：
```shell
del demo-ai-v1.tar.gz
docker build -t demo-ai:v1 .
docker save demo-ai:v1 -o demo-ai-v1.tar.gz
```
2. 服务器加载镜像
```shell
docker load -i /data/demo-ai-v1.tar.gz
```
3. 运行容器文件
```shell
cd /data/demo-ai

# Compose 自动停止旧容器并用新镜像重新创建
docker compose up -d \
  --force-recreate \
  --no-deps \
  xxx
```
